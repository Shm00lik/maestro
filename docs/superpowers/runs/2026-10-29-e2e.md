## Problems found
1. **Task worktrees are never cleaned up** after the mission ends: 5 task worktrees (and their branches) remain under `.claude/worktrees`. (Known deferred minor; now visible.)
2. **Read-only tasks print `[T1-review merged]`** though they have no commits (cosmetic).
3. **The "Allow? …" line is re-printed after every unrelated event** while a prompt is open (cosmetic, noisy).
4. **Prompt fatigue:** 7 of 10 prompts were task Bash commands. Agents write files and commit through Bash heredocs even though `acceptEdits` would auto-approve the Edit/Write tools. Product decision needed (see Open issues).
5. The conductor skipped a spec review for T3 (it reviewed T1 and T2). Prompt-level behaviour, not an engine bug.
6. Read-only reviewers cannot run tests, so the conductor ran them itself in the integration worktree (prompts 6 and 9).

## Open issues
- How to reduce permission prompts for routine task commands (`npm test`, `git add/commit` inside the task's own worktree) without weakening safety.
- Whether spec reviewers should be allowed to run tests.
- Conductor token usage is not shown in the final summary.
